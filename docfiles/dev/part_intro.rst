Developer & Contributor Docs: Building Together
================================================

*"If you want to go fast, go alone. If you want to go far, go together."* — African Proverb

Welcome, Developer
------------------

You're here because you want to go deeper. Maybe you've found a bug and want to fix it. Maybe you have an idea for a new feature. Maybe you're curious about how py3plex works under the hood. Whatever brought you here, welcome.

Open-source software is built by communities. py3plex exists because researchers and developers contributed their time, ideas, and code. This section helps you become part of that community.

What You'll Find Here
---------------------

**Development Guide** covers the practical aspects of contributing: how to set up a development environment, how to run tests, how to submit changes. If you're making your first contribution, start here.

**Code Architecture** explains how py3plex is organized internally. Understanding the architecture helps you navigate the codebase and make changes that fit with existing patterns.

**Repository Layout** provides a map of the codebase. Where do the core data structures live? Where are the algorithms? Where are the tests? This chapter answers these questions.

**Contributing Guidelines** describes the social and process aspects of contribution: how to report bugs, how to propose features, what to expect during code review.

The Value of Contributing
-------------------------

Contributing to open source is rewarding in many ways:

**For your skills:** Working on production-quality code with other developers improves your abilities faster than working alone.

**For your career:** Open-source contributions demonstrate competence to potential employers and collaborators in ways that private code cannot.

**For your research:** If you implement an algorithm for your research, contributing it to py3plex makes it accessible to the community and increases the impact of your work.

**For the community:** Every contribution, from fixing a typo to adding a major feature, makes py3plex better for everyone who uses it.

Types of Contributions
----------------------

Contributions come in many forms:

* **Bug reports:** Found something that doesn't work right? Report it. Clear bug reports are valuable contributions.

* **Documentation improvements:** Noticed an unclear explanation? Fixed a typo? Documentation quality directly affects user experience.

* **Code fixes:** Fixed a bug? Improved performance? Code contributions are the heart of open source.

* **New features:** Implemented a new algorithm? Added a new visualization? New features expand what py3plex can do.

* **Examples and tutorials:** Created a tutorial for your use case? Others will benefit from your work.

* **Community support:** Helping others in issues and discussions is a valuable contribution that builds community.

Getting Started
---------------

If you're new to contributing, we recommend:

1. Read the :doc:`development_guide` to set up your environment
2. Browse the GitHub issues for items labeled "good first issue"
3. Start with something small—a documentation fix or a simple bug
4. Ask questions when you're stuck—the community is friendly

A Note on Expectations
----------------------

We want contributing to be a positive experience. When you submit a contribution:

* Expect constructive feedback during code review
* Expect questions about design decisions—this is how we maintain quality
* Expect iteration—it's rare for contributions to be merged without changes
* Expect gratitude—we appreciate everyone who takes the time to contribute

Ready to Contribute?
--------------------

Start with :doc:`development_guide` to set up your environment, or browse the :doc:`contributing` guidelines to understand the process.

.. note::

   **First-Time Contributor?**
   
   If this is your first time contributing to an open-source project:
   
   * Don't worry about getting everything perfect—we're here to help
   * Start small—a typo fix is a perfectly valid first contribution
   * Ask questions early—it's better to clarify expectations than to waste time
   * Be patient—maintainers are often volunteers with limited time
   
   Welcome to the community!
